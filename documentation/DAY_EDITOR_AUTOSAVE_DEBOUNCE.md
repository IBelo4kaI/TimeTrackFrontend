# Объединение ввода DayEditor перед автосохранением

## Изменённые файлы этой задачи

- `src/stores/dayEditor.js`
- `documentation/DAY_EDITOR_AUTOSAVE_DEBOUNCE.md`

Существующие изменения редактора в рабочем дереве сохранены. UI, Floating UI, overlay, выделение, backend, API и аудит не изменены.

## Debounce и очередь

- Часы (стрелки и ручной ввод): trailing debounce 1000 мс. Тип, место и комментарий: 400 мс. Короткая задержка другого поля не сокращает уже ожидающую паузу часов; несколько параметров объединяются в актуальный draft.
- Используется один существующий `inFlight`, один таймер и общий срок готовности draft. Отдельной очереди снимков ввода нет.
- Во время HTTP ввод обновляет локальный draft и срок готовности. После подтверждения активного запроса цикл ждёт завершения последней серии ввода, затем строит следующий план из текущих значений. Промежуточные нажатия не накапливаются как отдельные операции.
- `flush()` принудительно снимает ожидание и возвращает тот же inFlight при активной записи. Закрытие ждёт подтверждения и проверки dirty/uncertain. Одновременный таймер не запускает второй запрос. Отправленные запросы не отменяются.
- Программная синхронизация и focus/select не вызывают `change()` и не заводят таймер.

## Проверка изменений

Одиночный редактор теперь хранит baseline как подтверждённые значения, сравнивает поля семантически и больше не использует JSON.stringify для dirty. Групповой редактор сохраняет существующее сравнение полей и индивидуальные исходные значения дат. У часов учитывается точность DECIMAL(5,2), у типа и места — действующая нормализация. Уже совпавшие дни пропускаются.

Временно пустые, нечисловые и незавершённые значения вроде `8.` не отправляются и блокируют безопасное закрытие до исправления. Полная дробь `.5` допустима. Часы по-прежнему ограничены диапазоном 0–24.

При синхронизации одиночного редактора обновляются только не затронутые пользователем поля; введённые во время запроса значения не перезаписываются. API требует полный набор полей записи: серверный контракт не заменён PATCH, остальные поля сохраняются из подтверждённого состояния. Обязательная нормализация места работы продолжает действовать.

Сверка результата, ожидания частично применённого пакета, перечитывание сервера перед повтором и сохранение draft при ошибке оставлены. Защита руководительского редактирования и обязательная причина не изменены.

## Когда история всё ещё содержит несколько событий

- Если пауза ввода истекла и запрос уже ушёл, следующее фактическое изменение создаёт новую запись аудита: отправленный запрос не отменяется.
- Группа содержит отдельные записи по датам; один логический пакет может создать событие для каждого реально изменённого дня.
- Смешанная группа с созданием и обновлением использует разные существующие API-операции. Аналогично удаление и обнуление часов отпуска остаются разными операциями.
- После частичного выполнения повторяются только неподтверждённые изменения. Уже сохранённая история не объединяется, не скрывается и не удаляется.

## Проверки

Исполнены `npm run build` и `git diff --check` — успешно. Vite сообщает о крупных chunks. Новые автоматизированные тесты, dev-сервер и живые API-проверки не запускались.

Следующие сценарии проверены по исходникам и требуют ручного подтверждения в браузере:

1. 8 → 9 → 10 → 11 → 12 с паузами менее секунды: до отправки остаётся только итоговое значение.
2. 8 → 9 → 8: семантическое сравнение с baseline исключает запрос. В группе пропускаются совпавшие даты.
3. Ручной ввод: пустое поле и `8.` не сохраняются; `8.25` сохраняется после паузы. Форматы 8, 8.0 и 8.00 эквивалентны, точность — два знака.
4. Офис → удалённо → офис за 400 мс: без записи при возврате к подтверждённому месту.
5. Часы и место за один интервал: место не сокращает часовую паузу, итоговый запрос содержит оба изменения.
6. Изменения во время HTTP: после подтверждения ждать актуального debounce; отправлять только последний draft, без конкурентного запроса.
7. Overlay/Escape до истечения таймера: принудительный flush и ожидание подтверждения.
8. Закрытие во время HTTP: тот же inFlight, затем последнее состояние без ожидания таймера; при ошибке окно и draft сохраняются.
9. Девять дней, четыре быстрых нажатия: один логический пакет итоговых значений; совпавшие даты исключаются.
10. Смешанные исходные значения: изменение одного поля сохраняет индивидуальные значения остальных; недоступные действия по-прежнему блокируются текущими проверками.
11. Частичное применение: существующие pendingGroup/сверка сохраняют неподтверждённые ожидания.
12. Неопределённый результат: повтор сначала читает сервер; уже применённые изменения не отправляются снова.
13. Руководитель без причины: отправки нет; после заполнения действует debounce и прежняя проверка комментария/work-only.
14. Одиночный редактор: создание, изменение, удаление, смена типа, десятичные часы, новые значения во время запроса и закрытие. После подтверждения незатронутые поля синхронизируются, введённые сохраняются.

Route guards `onBeforeRouteLeave`/`onBeforeRouteUpdate` продолжают вызывать `dayEditor.close()`. Открытие другого дня также ожидает close; переход при ошибке не разрешается. При смене контекста вне этих механизмов сохраняется прежняя проверка исходного сотрудника и месяца; новые пути навигации не добавлялись.
