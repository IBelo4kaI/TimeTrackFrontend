# Единый DayEditor для одного и нескольких дней

## Режимы и входы

Одиночный режим сохраняет прежние поля и очередь. Для нескольких дат тот же store/компонент получает active.days; active.day остаётся логичным anchor. В UI добавлены компактный счётчик, смешанные состояния и сообщения об ограничениях. Кнопки «Сохранить» и второй групповой формы нет.

Проверены все вызовы useAddReportModalStore: ControlsCalendar, DayListCalendar, DayListCalendarMobile. Их обычный open при нескольких выбранных днях направляет в DayEditor.openGroup. Toolbar показывает «Редактировать выбранные (N)», контекстное меню предоставляет редактирование, mobile — кнопку «Редактировать (N)» рядом с выбором. Само изменение selection редактор не открывает. Desktop dblclick и mobile tap одиночного дня не менялись.

Старая форма не удалена: доступна явным openLegacy(day); её существующие save/delete/валидация оставлены. В обычных входах поддержанные одиночные и групповые операции используют компактный редактор. Контекстные быстрые medical/decree/time-off/work/clear продолжают использовать прежние helpers; их семантика не переписана.

## Смешанные значения и явные изменения

Групповой черновик агрегирует реальные значения всех выбранных дней. Совпадающее поле отображается общим значением, различающееся — null и смешанным состоянием. Часы получают placeholder «Разные значения», +/- отключены до ввода общего числа. Для разных типов нет произвольного активного переключателя; отображается подпись «Разные типы». Место работы сравнивается среди рабочих записей, для которых оно применимо; о нерабочих/пустых датах показано количество.

editedFields фиксирует только поля, изменённые пользователем. Открытие, autofocus/select, прокрутка типов и ввод одного комментария не формируют изменений времени. Для каждого дня строится свой target из его текущих значений плюс явный patch; helper createUpdatesObjects сохраняет существующие правила сериализации, isEditType и место работы. Часы/тип/место остальных дней не берутся из первой даты.

Пример 6 ч/офис, 8 ч/офис, 4 ч/удалённо: выбор «Офис» создаёт обновление только третьей записи с прежними 4 ч. После подтверждения её значения становятся базой, общий patch снимается. Ввод 7 ч затем формирует один update-пакет из трёх дат с сохранением индивидуального типа и места.

Пустые дни не создаются при открытии. Если правка часов требует создания записи без существующего типа, редактор просит явно выбрать общий тип. Это намеренно исключает неявное назначение типа первой даты. Выбор общего типа действительно применяется ко всем датам, где он разрешён. Изменение только места работы применяется лишь к рабочим записям и не создаёт пустые дни; число остальных дат явно показано. Никакие 8 часов или офис всем датам автоматически не назначаются. Пустой или невалидный ввод часов не подтверждается как числовой 0; подтверждение численно одинакового значения не перезаписывает вводимый текст часов.

Смена типа на нерабочий сохраняет прежнюю бизнес-семантику очистки неприменимого места работы; изменение только часов тип не меняет.

## Сохранение и частичный успех

Используется прежний debounce 500 мс и единственный inFlight для всей сессии. Быстрые изменения объединяются; новые правки во время запроса остаются в draft. После ответа план строится заново по актуальному patch, не по устаревшему снимку.

Каждый пакет содержит один вид операции: update или create; это позволяет безопасно обрабатывать смешанные существующие/пустые дни и не отправлять запрещённый смешанный пакет manager endpoint. Используются calendar.updateDay, calendar.deleteDay и createUpdatesObjects. Формат запросов и backend не менялись. Совпадающие с target записи исключаются из пакетов.

Каждая операция использует штатное обновление calendar/statistics/history/month state через calendar store. После ответа наличие записей и значения сверяются с обновлёнными днями, затем они становятся подтверждённой базой. Если следующий пакет не прошёл, уже подтверждённые даты сохраняются и не записываются повторно без необходимости.

При неизвестном результате запроса uncertain остаётся true. Retry сначала читает текущий месяц с сервера и выполняет штатный initialFetch. Только после успешной сверки строится новый план: существующая запись обновляется, отсутствующая создаётся, совпадающая не отправляется. Настоящие ошибки/некорректный или неполный ответ не подменяются успехом. HTTP/БД не дают общей транзакции между несколькими пакетами; уже подтверждённые пакеты не откатываются. В исходной схеме также уже существует unique_user_date (user_id, entry_date); это ограничение не менялось и не проверялось на работающей БД.

Close ждёт flush и проверяет dirty/uncertain; при ошибке, невалидных полях или отсутствии причины окно остаётся открытым. Escape, overlay и прежние route guards используют тот же close. Компактное действие «Отменить оставшиеся правки» отменяет только ещё не подтверждённый patch по явному решению пользователя; выполненные серверные изменения оно не откатывает. Неопределённый результат всё равно сверяется перед закрытием.

## Ограничения и очистка

Для руководителя managerDayError проверяется для каждой выбранной даты до пакетов. При недоступных датах отображается их число и изменения блокируются для всей группы, без молчаливого пропуска. Комментарий обязателен для соответствующих scoped create/edit/delete. Типы ограничены work-only; actor_id/actor_type не отправляются. Backend остаётся основной проверкой прав.

Для неизменяемых типов (isEditType=false, в частности отпусков) нельзя выбрать несовместимый общий тип. Часы таких дней редактируются только по прежним правилам обычного/административного календаря. Не добавлялся общий запрет на прежнее административное редактирование нерабочих типов.

Очистка — отдельное явное действие. Обычные существующие записи удаляются delete-пакетом, отпускные остаются и получают 0 часов, пустые даты не создаются и не удаляются. Уже нулевые отпускные и уже удалённые даты повторно не отправляются. Для руководителя действуют прежние проверки, включая защищённые кадровые/system-записи.

## Selection, overlay и Floating UI

В selecting store isGroupEditing временно защищает selection от clearSelection при initialFetch и смене desktop/mobile. Во время сохранения количество выбранных дат не обнуляется. После подтверждения выбранные объекты синхронизируются по датам с серверными значениями. После закрытия группы обычный selection сохраняется; снимается только временный класс редактора.

В контекстном меню принадлежность selection проверяется существующим isItemSelected (по дате), а не Set.has по ссылке: после refresh экземпляры дней меняются.

Оба компонента дня используют isEditedDay для подсветки всех дат группы. Сохраняется уже действующий порядок слоёв: fullscreen overlay → реальные выделенные Grid-ячейки → popover. Копий, отверстий clip-path и изменения Grid нет. Групповой/одиночный временный класс исчезает при закрытии.

DOM anchor регистрируется только для active.day, не каждой выделенной ячейкой. Выбирается последний выбранный день группы либо последний добавленный элемент selection; при отсутствии пригодного DOM работает существующий viewport fallback. После refresh anchor регистрируется новым компонентом. useDayEditorPosition.js, middleware и cleanup autoUpdate не менялись.

## Ручная матрица для тестового окружения

| Сценарий | Ожидается |
|---|---|
| 1. Одиночный день | Прежние dblclick/tap, autofocus desktop, create/update/delete, история и статус месяца. |
| 2. Несколько дней | По явному действию один DayEditor со счётчиком, без автоматического открытия при выборе. |
| 3. Общие значения | Показаны реальные общие часы/тип/место, открытие ничего не пишет. |
| 4. Смешанные значения | Нейтральные поля; +/- не используют часы первого дня. |
| 5. Только место, затем часы | Пример 6/8/4 ч сохраняет часы при смене места; после ввода 7 все получают 7. |
| 6. Пустые дни | Явный тип создаёт записи; часы не получают автоматически 8. |
| 7. Существующие + пустые | Updates и creates идут отдельными последовательными пакетами; существующие ID не создаются заново. При отсутствии типа для пустых дат показана валидация. |
| 8. Защищённые даты | Количество недоступных дат видно; manager-группа блокируется целиком, отпускной тип не конвертируется. |
| 9. Причина руководителя | До непустой причины запросов нет; только work и существующий scoped endpoint. |
| 10. Быстрые правки | Одна очередь, debounce, свежий patch после каждого ответа, без параллельных перезаписей. |
| 11. Частичный успех/сбой | Панель с ошибкой остаётся; retry перечитывает сервер, подтверждённые значения не дублируются. |
| 12. Закрытие во время записи | Закрытие/route guard ждут очередь; ошибки и несохранённое не скрываются. |
| 13. Overlay | Все выбранные дни яркие над затемнением sidebar/header/страницы, после закрытия остаётся только обычный selection. |
| 14. Границы viewport | Прежние flip/shift/size/arrow, autoUpdate при scroll/resize/комментарии/ошибке. |
| 15. Выбор desktop/mobile | Drag/Ctrl/Cmd/Shift и «Выбрать» сохранены; mobile имеет явную кнопку редактирования, клавиатура сама не открывается. |
| 16. Legacy/особые операции | openLegacy сохранён; быстрые контекстные операции используют прежние helpers, очистка отпусков обнуляет часы. |
| 17. Resize при открытой группе | Selection не теряется при смене компонентов, anchor восстанавливается по конкретному дню. |
| 18. Повторное открытие после частичного успеха | Выбранные даты перечитываются из текущего календаря, не используются устаревшие значения Set. |
