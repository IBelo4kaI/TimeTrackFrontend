# Позиционирование редактора дня через Floating UI

## Изменения

Использована установленная @floating-ui/dom. package.json, lockfile, backend и API не менялись. Автосохранение, debounce, очередь запросов, проверки руководителя, комментарий и групповая форма сохранены.

Позиционирование вынесено в src/composables/useDayEditorPosition.js. В DayEditor.vue остались отображение панели, управление фокусом и отдельное сохранение ссылки на контейнер календаря для прокрутки. Компонент полностью не переписывался.

Удалены ручная функция place, расчёт стороны/координат панели по предполагаемой геометрии, ручной clamp, поиск anchor через document.querySelector по дате, lastAnchor и собственные ResizeObserver/MutationObserver. Удалены их подписки на document scroll, window resize и visualViewport. Измерение реальной ячейки сохранено только для overlay; прокрутка строки типов — отдельное прежнее поведение.

## Floating UI

computePosition использует strategy: fixed; панель остаётся в Teleport/body вне overflow календаря.

- offset(12) — расстояние от anchor.
- flip — desktop-предпочтение right с fallback left, bottom, top; используется viewport.
- shift — отступ 12 px, коррекция обеих осей в пределах viewport.
- size — доступные ширина/высота из middleware задаются через --editor-width/--editor-height. Существующая ширина desktop 300 px и mobile 420 px сохранена; библиотека ограничивает её доступным пространством. Высота определяется содержимым, при нехватке места прокручивается editor-content.
- arrow — реальный элемент вместо псевдоэлемента. Его x/y берутся из middleware; противоположная placement сторона получает -7 px. CSS поддерживает right, left, bottom, top. Для mobile/fallback стрелка скрыта.

Floating UI автоматически измеряет реальную панель. Появление комментария/ошибки, изменение её размеров, scroll, resize и layout shift обслуживает autoUpdate. Библиотека установленной версии подписывает overflow ancestors, включая window.visualViewport.

## Anchor и обновление календаря

Store хранит отдельный shallowRef anchorElement для DOM-элемента. Это состояние представления, не новая структура данных запроса или изменения бизнес-модели active/day. Открытие по двойному клику/тапу передаёт конкретный event.currentTarget. Режим открытия, ограничения и групповые жесты не менялись.

Desktop/mobile-компоненты дня регистрируют свой template ref, когда становятся редактируемым днём. При размонтировании освобождают anchor только если он всё ещё указывает на них. После обновления календаря новый экземпляр ячейки регистрирует новый элемент. Путь открытия из кнопки календаря без переданного DOM-элемента также получает anchor от компонента дня, без поиска по дате в DOM.

initialFetch штатно временно удаляет ячейки во время сохранения. В этот промежуток или при отсутствии ячейки используется обоснованный fallback: виртуальный anchor внизу видимого viewport. Он не сохраняет старые координаты дня. Панель остаётся доступной, черновик/ошибка не теряются, выделение старой DOM-ячейки исчезает вместе с ней. После появления нового конкретного элемента привязка восстанавливается. Отсутствие anchor не вызывает повторной записи времени и не обходит безопасное close().

Mobile всегда использует такой viewport anchor с placement top: панель находится у нижней границы видимой области, с учётом visualViewport и клавиатуры. Shift/size ограничивают её видимой областью; содержимое доступно прокруткой.

## Cleanup и асинхронность

Возвращённая autoUpdate функция вызывается при закрытии, смене anchor, смене mobile/desktop и размонтировании компонента. Она снимает подписки и внутренние ResizeObserver/IntersectionObserver. Watcher создан внутри Vue setup и автоматически останавливается при unmount.

Каждый lifecycle имеет generation, каждый расчёт — последовательный request. Перед применением size и результата проверяются generation, request, активная сессия, DOM-элемент панели, актуальность anchor и мобильного режима. Отсоединённый anchor сбрасывается. Поздний результат не может изменить закрытую панель или применить положение предыдущего дня.

Первое появление панели скрыто через visibility до завершения расчёта, при этом размеры доступны библиотеке. Фокус/выделение часов и прокрутка к активному типу выполняются один раз на сессию после применения первого результата. Изменение anchor при refresh, новое сохранение и изменение высоты не сбрасывают ввод и фокус. Прежнее плавное появление сохранено.

При неожиданной ошибке измерения выводится ошибка в консоль, панель остаётся доступной в ограниченной CSS-начальной позиции вместо зависания невидимого редактора. Это аварийный путь, не основной механизм позиционирования.

## Overlay и оригинальная ячейка

Вырез clip-path и updateOverlay удалены. Полноэкранный overlay и popover — независимые Teleport/body-соседи, каждый со своим fade-переходом. Общая fixed-обёртка с z-index/opacity убрана: иначе исходную ячейку за пределами обёртки нельзя расположить между её дочерними слоями.

Проверена цепочка #app → MainLayout → main → страница календаря → container-row/calendar (desktop) либо calendar/calendar-grid (mobile). В ней нет transform, filter, isolation, opacity < 1 или заданного z-index, изолирующих день. Grid/flex без z-index сами по себе не изолируют его. Overflow auto у desktop-сетки ограничивает её прокрутку, но не создаёт stacking context. Внутренние isolation/transform у именинников — потомки дня и не мешают поднятию самой ячейки.

Использован локальный класс day-editor-active: position relative без смещения и z-index 10002. Overlay расположен на 10001 (прежний editor layer, выше контекстного меню приложения на 10000), popover — на 10003. Это три соседних слоя, а не попытка преодолеть родительский stacking context большим числом. Две новые границы выбраны относительно уже существующего слоя редактора.

Оригинал остаётся Grid-элементом: его размеры, место в сетке и содержимое не меняются, копий и placeholder нет. Цвета и тонкая рамка сохранены. Pointer-events none только для открытого дня передаёт клики overlay и исключает случайный запуск истории/редактирования под открытой панелью. После закрытия класс исчезает, исходные взаимодействия возвращаются. Групповое выделение использует отдельный прежний класс.

Положение дня при scroll/resize обеспечивает сам layout; синхронизировать вторую геометрию больше не требуется. При размонтировании anchor его выделение удаляется вместе с DOM-узлом; новый компонент регистрирует новый anchor и класс, а Floating UI сохраняет прежний lifecycle и временный viewport fallback. Копий и устаревших прямоугольников нет.

Floating UI и onAnchorUpdate не изменены: callback теперь только сохраняет ближайший .calendar для перенаправления wheel под overlay. Никаких дополнительных подписок/наблюдателей не добавлено. Остались безопасные close/flush, Escape и клики снаружи; fade не начинается до успешного закрытия. Существующие outside/Escape/beforeunload-обработчики удаляются при unmount страницы, autoUpdate — при закрытии/смене anchor/unmount.

Проверено по исходникам: слой над sidebar/header, исходная ячейка между overlay и popover, отсутствие изменения Grid, удаление временного класса при закрытии и исчезновении anchor, отсутствие копирования DOM и второй системы геометрии. Браузерная проверка слоёв, scroll/resize и визуальных переходов не выполнялась.

## Проверки

До рефакторинга и после него выполнен npm run build. Финально выполнен git diff --check. Новые автоматизированные тесты не писались. Сборка сохраняет предупреждение о chunks больше 500 kB.

Сценарии ниже проверены по исходникам; браузер, dev-сервер, реальные HTTP-запросы и экранная клавиатура не запускались. Визуальное подтверждение на целевых браузерах требуется вручную.

| Сценарий | Ожидаемое поведение и механизм |
|---|---|
| Левый край | Right по умолчанию; offset 12, viewport padding 12. |
| Правый край | Flip в left; при нехватке бокового пространства — bottom/top. |
| Первая/последняя неделя | Flip/shift выбирают доступную сторону и корректируют координаты; arrow соответствует результату. |
| Открытие при прокрученном календаре | Конкретный DOM anchor измеряется заново, не используются сохранённые старые координаты. |
| Scroll/resize при открытой панели | autoUpdate обновляет панель; оригинальная ячейка следует layout; размеры панели ограничены viewport. |
| Комментарий/ошибка меняют высоту | Внутренний ResizeObserver autoUpdate запускает computePosition с реальными размерами, size ограничивает высоту. |
